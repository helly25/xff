# MemorySanitizer RUNTIME suppression file, loaded by MSAN_OPTIONS=suppressions=... (see
# .bazelrc --config=msan). MSan reads it when a test PROCESS starts, so it reaches the
# binary as a runfile: xff/cc.bzl's cc_test / cc_binary wrappers add it to `data` under
# --config=msan, which is what puts it next to the test at run time.
#
# EMPTY ON PURPOSE. It held one entry, for a report that EVERY test hit at static-init time
# inside absl's flag registry. That was never an absl bug and never an xff bug: the
# `std::string` frames resolved to the PREBUILT, uninstrumented libc++ in the hermetic LLVM
# distribution, so MSan had written no shadow for the temporary the comparison read. Since
# --config=msan now builds against a genuinely INSTRUMENTED libc++ (toolchains_llvm's
# `--features=msan` plus the `libcxx_url` overlay, see bazelmod/llvm.MODULE.bazel) the report
# is gone at its source and the entry is deleted rather than carried.
#
# The plumbing stays so a genuine future false positive has a home. NOTE on what this format
# can express: MSan's runtime suppressions understand only `interceptor_via_fun` and
# `interceptor_via_lib` (reports raised through an intercepted libc call). There is no general
# `fun:` / `src:` form here - those exist only in the compile-time -fsanitize-ignorelist.
