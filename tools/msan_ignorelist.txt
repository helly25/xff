# MemorySanitizer ignore list (clang -fsanitize-ignorelist, loaded by --config=msan in
# .bazelrc). Code matched here is compiled WITHOUT MSan instrumentation, so MSan raises no
# report from it. Keep it minimal: every entry is a place we have decided not to check.
#
# Why an ignore list and not `MSAN_OPTIONS=suppressions=`: MSan's runtime suppression file
# only understands `interceptor_via_fun` / `interceptor_via_lib`, i.e. reports raised
# through an intercepted libc call. The report below is raised by instrumented inline code
# (`std::string::__is_long`), not by an interceptor, so a runtime suppression cannot match
# it. The compile-time ignore list is the mechanism that applies.
#
# ---------------------------------------------------------------------------------------
# absl's flag registry, hit by EVERY test at static-init time:
#
#   #0 std::__1::basic_string<...>::__is_long()   toolchains_llvm.../include/c++/v1/string
#   #1 std::__1::basic_string<...>::size()        toolchains_llvm.../include/c++/v1/string
#   #2 std::__1::operator==<char, ...>(...)       toolchains_llvm.../include/c++/v1/string
#   #3 absl::flags_internal::FlagRegistry::RegisterFlag(...)  absl/flags/reflection.cc:119
#   #6 __cxx_global_var_init                                  absl/flags/parse.cc:111
#   Uninitialized value was created by an allocation of 'ref.tmp' in RegisterFlag
#
# This is a KNOWN FALSE POSITIVE, and the stack says why: the `std::string` frames resolve
# to `external/toolchains_llvm.../include/c++/v1/string`, the PREBUILT (uninstrumented)
# libc++ from the hermetic LLVM distribution - not to the instrumented `.msan-libcxx` copy
# that `--config=msan` is supposed to swap in. The `ref.tmp` temporary is therefore
# constructed by code MSan never saw, so no shadow is written for it, and the `==` compare
# in RegisterFlag reads it as uninitialized. Nothing in xff (or in absl) is wrong here.
#
# Scope is one translation unit on purpose: only reflection.cc is skipped, so any OTHER
# uninitialized read - including a real one anywhere else in absl or in xff - still fails
# the build. The proper fix is completing the standard-library swap so libc++ itself is
# instrumented (`-nostdinc++` plus the `.msan-libcxx` -isystem is evidently not winning
# over the toolchain's builtin include dirs); when that lands, delete this entry and check
# that the cell stays green. Tracked in TODO.md under the MSan investigation.
